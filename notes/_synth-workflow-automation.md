# 워크플로우 자동화 종합

## 공통 핵심: "반복 업무를 시스템이 대신 실행하게 만드는 것"

모든 노트가 동의하는 하나의 방향이 있다. **사람이 직접 하던 반복 단계들을 AI가 연결·실행하도록 설계하면, 사람은 판단 3가지만 하면 된다**는 것이다. 주관 보고를 쪼개면 39단계인데 사람 몫은 단 3가지였다는 실증이 이를 뒷받침한다. [[2026-06-25-클로드-AI-업무-자동화-3단계]]

---

## 서로 다른 관점 & 강조점

### 1. "어떻게 쪼갤 것인가" (설계 관점)
자동화의 출발점은 도구가 아니라 **업무 분해**다. AI와 함께 행동 단위까지 쪼개고, AI 몫과 사람 몫을 분리한 뒤 스킬·커넥터로 연결한다. [[2026-06-25-클로드-AI-업무-자동화-3단계]]

### 2. "어떻게 실행할 것인가" (기술 관점)
- **다이나믹 워크플로우**: 요청마다 AI가 스스로 단계를 설계하고 수백 개 서브에이전트를 병렬 실행 — 외부 도구 없이 Claude 내부에서 처리 [[2026-06-04-클로드-코드-Dynamic-Workflow-기능-비교-총정리]] [[2026-05-23-아직도-클로드코드에-외부-툴-붙이세요-이제-다-안에-있습니다]]
- **Computer Use(코워크)**: AI가 컴퓨터를 직접 조작해 웹스크래핑→보고서 작성→업로드→메신저 발송까지 5단계를 단일 명령으로 처리 [[2026-05-22-카카오톡으로-클로드가-들어왔습니다]]
- **커스텀 ERP**: API를 연결해 사내 전 업무 데이터를 한 곳에 모아 AI가 분석·실행하는 자체 플랫폼 구축 [[2026-05-23-토스-PO-출신-대표가-사내-ERP와-AI-에이전트를-직접-만들고-AI]]
- **마크다운 + 프롬프트 자동화**: .md 파일로 고정 지시를 저장해두면 매번 입력 없이 재실행 [[2026-05-22-클로드-코드로-어떤-유튜브-채널이든-복사하는-방법-코딩-필요-없음]]

### 3. "어떻게 위임할 것인가" (프롬프트 관점)
세세한 방법 지시가 오히려 AI 자율성을 망친다. **'왜 하는가' 맥락을 주고, 되돌릴 수 없는 행동·범위 이탈·사용자 입력 필요 시 3가지 경우에만 멈추게 경계를 설정**하면 더 나은 결과가 나온다. [[2026-07-03-유능한-페이블을-바보로-만들지-마세요-명령은-줄이고-이유를-말하세요]]

## 주의점·상충

- **리서치 자동화**: 딥리서치는 검증 단계에서 에이전트 5배를 쓰는 반면, 토큰 대비 효율은 코드 작업보다 낮다 — 용도에 따라 선택 필요 [[2026-06-01-아직도-클로드코드에-외부-툴-붙이세요-이제-다-안에-있습니다]]
- **프롬프트 과잉 설계 위험**: 기존에 공들여 만든 세세한 프롬프트가 오히려 자동화 품질을 떨어뜨릴 수 있다 [[2026-07-03-유능한-페이블을-바보로-만들지-마세요-명령은-줄이고-이유를-말하세요]]
- **API 제한**: 카카오톡처럼 개인용 API가 닫힌 도구는 마우스/키보드 조작 우회만 가능 [[2026-05-22-카카오톡으로-클로드가-들어왔습니다]]
