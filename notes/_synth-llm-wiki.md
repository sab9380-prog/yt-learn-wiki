# LLM 위키 (llm-wiki) 종합

## 핵심 정의 (노트들이 공통으로 말하는 것)

LLM 위키는 **AI가 자료를 읽고 → 핵심만 추출해 → 위키 형태로 정리·연결·갱신하는** 개인 지식 시스템이다. 안드레이 카파시가 제안한 개념으로, 단 하나의 트윗이 며칠 만에 바이럴되어 새로운 지식 관리 트렌드가 됐다. [[2026-05-22-카파시가-모두의-Claude-Code를-10배-향상-시켰습니다]] [[2026-05-22-Claude-Code보다-중요한-AI-OS-설계]]

---

## 왜 필요한가 — 해결하는 문제 2가지

| 문제 | 결과 |
|---|---|
| AI는 대화가 끝나면 맥락을 모두 잊음 (기억 상실) | 매번 제로베이스에서 재설명 |
| AI가 원본 문서를 매번 처음부터 읽음 (토큰 낭비) | 47,000토큰 → 7,700토큰으로 84% 낭비 [[2026-05-22-AI-토큰-84-절감-LLM-Wiki-패턴-Karpathy가-제안한]] |

## 작동 구조 (3층)

```
로우소스(원본 자료) → 위키(AI가 정리한 핵심 요약) → 스키마(규칙·구조)
```

AI가 새 자료를 **인제스트**(소화)할 때마다 기존 위키를 업데이트하고 교차 참조를 자동 연결한다. 지식이 '복리'처럼 쌓인다. [[2026-05-22-안쓰면-손해-클로드코드가-내-노하우를-나무위키처럼-정리해줍니다-feat]] [[2026-06-15-옵시디언-하나에-모든-AI-에이전트-연결]]

## 활용 방식 3가지 (노트 4의 분류)

- **브레인형** — 전문 지식 누적 → AI의 두뇌 확장
- **메모리형** — 작업 연속성 확보 → AI의 기억 장치
- **거울형** — 질문·사고 패턴 기록 → 자기 객관화

## 서로 다른 강조점 — 주의해서 볼 부분

**"뭐든 넣어도 된다" ❌ vs "선별이 핵심" ✅**
- 아무 자료나 넣으면 쓰레기 위키가 된다(GIGO). 반복 사용·의사결정 영향·업무 연결 3가지 기준 중 2개 이상 해당할 때만 포함. 정리에 5분 이상 걸리면 보류. [[2026-06-12-옵시디언-LLM-Wiki-아무-자료나-넣으면-안-됩니다]]
- "목적성 있는 수집이 되어야 골드가 된다." [[2026-05-24-카파시의-LLM-Wiki로-나만의-AI-세컨드-브레인-만들기-이것만]]

**"도구만 세팅하면 된다" ❌ vs "목적이 먼저" ✅**
- 방법론만 따라 하면 한두 달 안에 실패한다. 개인의 철학·목적이 없으면 LLM 위키는 외부 지식의 얕은 컴파일에 불과하다. [[2026-05-22-Claude-Code보다-중요한-AI-OS-설계]]

**개인용 vs 팀용 — 맥락 오염 리스크**
- 개인은 오류가 생겨도 다시 설명하면 되지만, 팀에서는 AI의 환각이 위키에 저장되어 전체 시스템으로 전파된다(맥락 오염). 저장 필터가 필수. [[2026-06-15-옵시디언-하나에-모든-AI-에이전트-연결]]

## 실전 적용 포인트

- **도구 조합:** 옵시디언(저장·시각화) + 클로드 코드(위키 생성·갱신) + 마크다운(AI 친화 형식) [[2026-05-22-옵시디언-LLM-Wiki로-만드는-나만의-AI-업무-시스템]]
- **RAG 대비 장점:** 벡터 DB 불필요. 마크다운 폴더 하나면 충분. 대신 대규모(수십만 건)는 RAG가 적합. [[2026-05-22-Andrej-Karpathy-덕분에-모두의-Claude-Code가]]
- **토큰 절약:** 83개 파일 → 81배 압축, 실제 60~95% 절감 사례 다수. [[2026-05-22-세계가-주목한-Karpathy-LLM-Wiki-진짜-돌아가는-도구를]]
- **팀 적용 시:** 리서치→기획→디자인→개발까지 하나의 위키로 전체 프로세스 관리 가능. [[2026-06-15-옵시디언-하나에-모든-AI-에이전트-연결]]

## 한 줄 정의

> **LLM 위키란, AI가 내 자료를 직접 읽어 요약·연결·갱신하는 개인 지식 시스템으로 — 대화가 끝나도 맥락이 사라지지 않고 복리처럼 쌓이는 AI 전용 두뇌다.**
