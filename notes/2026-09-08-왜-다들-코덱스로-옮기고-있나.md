# 왜 다들 코덱스로 옮기고 있나 — 아스트라가 바꾼 것

## 🧠 이해 (Understand)
- **Summary:** 매일 코딩에 사용하는 두 도구인 코덱스(Codex)와 클로드 코드를 비교한 실사용 체감 리뷰다. 핵심 결론은 '코딩은 코덱스, 자동화는 클로드 코드'로 역할이 갈렸다. 코덱스의 아스트라 모델이 긴 작업에서 규칙을 끝까지 유지하고, 브라우저 자동화·백엔드 작업에서 중단 없이 완주하며, 한도가 넉넉해 마음껏 실험할 수 있다는 점이 결정적이었다. 클로드 코드의 페이블 모델은 어려운 문제에 강하지만 토큰 소진이 빨라 하루 종일 쓰는 도구로는 부적합하다. 도구 위에 쌓아둔 규칙 파일(하니스)도 최신 모델에는 오히려 방해가 되어 순정 사용으로 돌아갔다.
- **Core Message:** 코딩 작업은 컨텍스트를 끝까지 유지하고 한도가 넉넉한 코덱스(아스트라)로, 자동화 파이프라인은 클로드 코드로 역할을 나누는 것이 현시점 최선의 선택이다.
> 일을 시킨 게 아니라 같이 한 셈이니까요.
> 좋은 걸 아껴 쓰는 상태가 되면, 그건 이미 주력이 아닙니다.
> 이 판은 계속 바뀝니다. 반년 전이었으면 반대로 얘기했을 겁니다.
❗ 하니스(규칙 파일·스킬)를 전부 걷어내고 순정 사용으로 돌아갔더니 오히려 더 편해졌다.
❗ 코덱스는 코드를 고친 뒤 스스로 실행해 오류를 확인하고 다시 수정한다 — 사용자의 검토 왕복 단계가 사라진다.
❗ 브라우저 자동화에서 한 칸 어긋나면 이후 모든 동작이 헛수고가 되는데, 코덱스는 화면 로딩을 기다렸다가 재시도해 이 문제를 크게 줄였다.

## 📚 핵심 용어
- **아스트라:** 코덱스에서 사용하는 모델로, 긴 작업에서도 초기 규칙을 끝까지 유지하는 능력이 특징이다. / 마라톤 선수처럼, 42km 내내 처음 세운 페이스 전략을 잃지 않고 완주한다. / 페이블은 단거리 폭발력이 강하지만 중간에 연료(토큰)가 떨어진다. 아스트라는 느려도 끝까지 간다.
- **하니스:** AI 도구 위에 사용자가 직접 만들어 얹는 규칙 파일·스킬·자동화 껍데기 구조물이다. / 자동차에 붙이는 에코 드라이빙 보조 장치처럼, 차(AI)가 제멋대로 굴 때 잡아주려고 얹는 보조 장치다. / 하니스는 예전 모델의 단점을 보완하려는 장치다. 최신 모델은 말로만 해도 따르므로 오히려 낡은 규칙이 발목을 잡는다.
- **컨텍스트 유지:** AI가 작업 초반에 받은 규칙·목표를 마지막 파일까지 잊지 않고 일관되게 적용하는 능력이다. / 요리사가 10가지 요리를 낼 때 첫 요리의 간 기준을 마지막 요리까지 그대로 유지하는 것과 같다. / 컨텍스트 유지는 작업 전체를 일관되게 완주하는 힘이다. 단순 성능(정확도)과 달리, 이게 무너지면 중간마다 사람이 개입해야 한다.
- **토큰 한도:** AI 도구가 하루에 처리할 수 있는 사용량 상한선으로, 소진되면 작업이 잠긴다. / 연료통 크기와 같다. 엔진(성능)이 좋아도 연료가 오전에 바닥나면 목적지까지 못 간다. / 모델 성능은 순간 최고속도, 토큰 한도는 연료통 크기다. 하루 종일 쓰는 사람에게는 한도가 성능만큼 중요하다.
