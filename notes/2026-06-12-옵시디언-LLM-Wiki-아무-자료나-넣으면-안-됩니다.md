## 🧠 이해 (Understand)
- **Summary:** 옵시디언으로 LLM 위키를 만들 때 자료 선별 기준과 Vault 구조 설계 방법을 설명한 영상입니다. 자료 선별 기준은 반복 사용, 의사결정 영향, 업무 연결의 3가지이며, 이 중 2개 이상에 해당하면 포함합니다. Vault는 처음부터 부서별로 나누지 말고 하나로 시작하되, 부서 구분은 폴더가 아닌 속성으로 관리하라고 권합니다. AI가 읽을 수 있도록 출처와 맥락을 함께 남기고, 5분 이내로 처리할 수 있는 자료만 넣어야 한다고 강조합니다.
- **Core Message:** LLM 위키는 자료창고가 아니라 AI가 읽고 판단하는 맥락 시스템이므로, 체계적인 선별 기준과 구조화가 필요하다
> Wiki를 채우려고 자료를 만들지 마세요. Wiki는 채우는게 목표가 아닙니다. 어차피 발생하는 것들을 흘려보내는 통로입니다

❗ 옵시디언의 링크, 백링크, 그래프뷰, 검색 등 핵심 기능이 모두 Vault 단위로만 작동함
❗ 현실 업무 자료 대부분이 부서 2-3개에 걸쳐 있어 부서별 분류가 실제로는 불가능함

## 📚 핵심 용어
- **LLM 위키:** AI(LLM)가 읽고 활용할 수 있도록 구조화된 개인/조직 지식 시스템 / 도서관처럼 정리된 자료실이 아니라, AI 비서에게 업무 맥락을 알려주는 참고서 더미 / 일반 위키는 사람이 읽기 위한 것, LLM 위키는 AI가 읽고 판단하기 위한 것 - 구조화 방식과 입력 기준이 다름
- **맥락 시스템:** 단순한 자료 저장이 아니라 AI가 상황을 이해하고 적절한 판단을 내릴 수 있도록 배경 정보를 제공하는 체계 / 요리할 때 레시피만 주는 것 vs 요리 상황, 먹는 사람, 목적까지 알려주는 것 / 자료창고는 저장이 목적, 맥락 시스템은 AI의 올바른 판단이 목적
- **Vault:** 옵시디언에서 노트들이 저장되는 최상위 단위로, 링크와 검색이 작동하는 범위 / 아파트 단지 - 단지 안에서는 모든 집이 연결되지만, 다른 단지와는 분리됨 / 폴더는 같은 Vault 내 분류, Vault는 완전히 독립된 공간 - 나누면 연결이 끊어짐
- **속성 기반 분류:** 폴더 대신 노트 상단에 메타데이터(타입, 부서, 프로젝트 등)를 붙여 다차원으로 분류하는 방식 / 책을 한 서가에만 꽂는 것 vs 여러 태그를 붙여 다양한 방식으로 찾을 수 있게 하는 것 / 폴더는 한 곳에만 분류 가능, 속성은 여러 기준 동시 적용 가능
