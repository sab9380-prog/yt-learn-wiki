## 핵심 개념: 모든 노트가 공통으로 말하는 것

**"사람(또는 오케스트레이터)이 병목이 되지 않도록, 여러 AI 에이전트에게 역할을 나눠 동시에 일을 시키는 구조"**

단일 AI와의 1:1 대화는 순차 처리라 사람이 기다려야 한다. 멀티 에이전트는 오케스트레이터 1개가 여러 서브 에이전트에게 작업을 병렬 위임해, 사람이 한 에이전트를 기다리는 동안 다른 에이전트는 이미 다음 일을 한다. ## 실전 적용 방법

1. **구조 먼저, 실행 나중** — 에이전트 여러 개를 켜기 전에 "누가 무엇을 어떤 순서로" 하는 scaffolding 문서를 먼저 작성한다 [[2026-07-13-1-AX인재전쟁-라이브-2시간만에-우승-도전합니다]]
2. **CronJob으로 24시간 가동** — 자는 동안에도 에이전트가 리서치·배포·리포트를 자동 실행하도록 시간 예약 설정 [[2026-07-02-메타-개발자가-육아하면서-부업-4개-돌리는-유일한-방법]]
3. **Discord·채널로 컨텍스트 분리** — 프로젝트별 채널을 만들어 에이전트들의 기억이 섞이지 않게 독립 관리 [[2026-05-22-클로드와-Codex가-자동-티키타카하며-개발하는-셋업-보여드립니다-회의]]
4. **복잡도 먼저 판단** — 단순 작업은 단일 에이전트가 3배 빠르다. 멀티 에이전트는 진짜 병렬성이 필요할 때만 [[2026-05-22-GSD-Superpowers-Claude-Code-중-누가-새로운-AI]]

## 상충·주의점

> ⚠️ **멀티 에이전트는 강력하지만, 제어를 잃으면 오히려 독이 된다**

- 무한 루프 → 10분에 수백 달러 API 비용 폭증 [[2026-05-22-RISK-AI-에이전트-프레임워크를-잘못-고르면-2026년-프로젝트는]]
- 추상화가 높을수록 디버깅이 어렵고, 배포 단계에서 90%가 실패 [[2026-05-22-RISK-AI-에이전트-프레임워크를-잘못-고르면-2026년-프로젝트는]]
- 화려한 오케스트레이션 도구(GSD)가 기본 도구보다 6배 느리고 6배 비쌀 수 있다 [[2026-05-22-GSD-Superpowers-Claude-Code-중-누가-새로운-AI]]
- **필수 안전장치**: 체크포인팅(중간 저장), Human-in-the-loop(고위험 단계 인간 승인), 상태 가시성 확보 [[2026-05-22-RISK-AI-에이전트-프레임워크를-잘못-고르면-2026년-프로젝트는]]

## 한 줄 정의

**멀티 에이전트란, 오케스트레이터(나 또는 AI)가 여러 AI 서브에이전트에게 역할을 병렬 위임해 "사람이 병목"이 되는 순간을 없애는 구조다 — 단, 제어·가시성·상태관리 없이 쓰면 비용과 혼돈만 폭증한다.**
