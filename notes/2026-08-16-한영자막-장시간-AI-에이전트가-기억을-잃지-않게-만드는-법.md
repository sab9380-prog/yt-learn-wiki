# \[한영자막\] 장시간 AI 에이전트가 기억을 잃지 않게 만드는 법 — Stefania Druga, Sakana.ai

## 🧠 이해 (Understand)
- **Summary:** 장기 실행 리서치 에이전트에서 컨텍스트 부패(context rot) 문제를 해결하기 위한 메모리 하네스 설계 실험을 소개한다. M3 Ultra 로컬 머신에서 Qwen 27B와 DeepSeek V4 Flash를 사용해 '쓰기-관리-읽기 루프' 구조의 하네스를 구축했다. 단순 벡터 RAG보다 결정 원장(decisions ledger)을 랭크 기반으로 우선순위화하는 방식이 가장 높은 성능을 기록했고, 비용도 더 낮았다. 태스크 전체가 컨텍스트에 들어갈 경우 메모리 하네스의 효과는 없지만, 장기 태스크에서는 구조화된 리콜 정책이 성능과 토큰 비용 모두에 유의미한 차이를 만든다. 로컬 모델에서 파이프라인 전체를 직접 통제함으로써 데이터 주권과 실험 가시성을 확보하는 것이 핵심 가치로 제시된다.
- **Core Message:** 장기 에이전트에서 '어떻게 기억할 것인가'보다 '무엇을 언제 어떻게 불러올 것인가(리콜 정책)'를 1급 지표로 설계해야 성능과 비용 모두 개선된다.
> Bad memory is expensive because it spends more tokens and it can send the agent the wrong way.
> Consider the recall policy as a first-class metric.
> When you can control every single step of the pipeline — I see that as an example of sovereignty.
❗ 오라클(정답 메모리)을 제공해도 최대 성능에 도달하지 못했다 — 모델이 올바른 메모리를 받아도 무시하거나 혼동하는 경우가 있기 때문.
❗ Coinbase CEO가 AI 비용을 줄이면서 사용량은 늘린 방법이 로컬 모델 전환 + 컨텍스트 정리 + 라우팅 개선이었다고 공개 트윗함.
❗ DeepSeek V4 Flash는 배치 쿼리를 지원하지 않아 68개 질문 평가를 직렬로 돌려야 했고, 비행기 안에서까지 평가를 실행했다.

## 📚 핵심 용어
- **메모리 하네스:** 에이전트 외부에서 메모리의 쓰기·관리·읽기를 제어하는 구조적 루프 시스템. / 비서가 회의 내용을 기록하고, 필요할 때 꺼내 보고해주는 역할을 에이전트 대신 외부에서 맡는 것. / 단순 DB 저장과의 차이: DB는 기록만 하지만, 하네스는 언제 무엇을 꺼낼지 판단하는 제어 로직까지 포함한다.
- **컨텍스트 부패:** 장기 태스크에서 컨텍스트가 넘쳐 모델이 이전 정보를 잊거나 자기모순에 빠지는 현상. / 책상이 너무 좁아 오래된 서류가 밀려나면서 앞서 한 결정을 잊고 같은 일을 두 번 하는 것과 같다. / 컨텍스트 윈도우 초과와 다른 점: 단순 초과는 오류로 멈추지만, 부패는 조용히 틀린 방향으로 계속 진행된다.
- **랭크 리콜 정책:** 저장된 메모리 중 우선순위 기준으로 순위를 매겨 가장 관련성 높은 것만 불러오는 리콜 방식. / 도서관에서 검색 결과를 관련도순으로 정렬해 상위 3권만 꺼내오는 것과 같다. / 벡터 RAG는 유사도로만 불러오지만, 랭크 리콜은 결정 중요도·순서 등 추가 기준으로 재정렬해 정밀도가 높다.
- **결정 원장:** 에이전트가 매 턴 내린 결정을 누적 기록해 우선순위화할 수 있도록 만든 구조화된 메모리 레이어. / 프로젝트 일지에 '오늘 내린 판단'을 날짜별로 적어두고 나중에 참조하는 것과 같다. / 아카이벌 블록이 세션 간 장기 정보를 보존한다면, 결정 원장은 현재 세션 내 판단 흐름을 추적하는 데 특화된다.
