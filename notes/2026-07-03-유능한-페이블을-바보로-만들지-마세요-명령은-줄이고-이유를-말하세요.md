## 🧠 이해 (Understand)
- **Summary:** 앤트로픽이 공개한 클로드 페이블 5 공식 사용 가이드의 핵심은 '더 많은 프롬프트'가 아니라 '더 나은 위임'이다. 페이블 5는 함수 하나가 아니라 며칠짜리 프로젝트를 통째로 받아 수십 개의 서브 에이전트를 병렬로 운용하며 수행하도록 설계됐다. 세세한 규칙보다 '왜 이 일을 하는지' 맥락과 이유를 설명할 때 모델이 더 나은 판단을 한다. 자율성을 주되 되돌릴 수 없는 행동, 범위 이탈, 사용자 입력 필요 시 세 경우에만 멈추게 하는 경계 설계가 중요하다. 검증은 수행 에이전트가 아닌 별도의 새 에이전트에게 맡기고, 경험은 마크다운으로 기록해 다음 작업에 활용해야 한다.
- **Core Message:** 페이블 5에게 일을 잘 맡기려면 명령을 더 붙이는 대신, 목적과 맥락을 설명하고 판단할 공간을 남겨두며 경계만 명확히 설정하라.
> 새로운 AI를 잘 쓰고 싶다면 명령을 더 붙이지 마십시오. 오히려 지금까지 공들여 만든 프롬프트부터 의심해 보십시오.
> 사정이 먼저고 부탁은 그다음입니다.
> 무엇을 더 적을지 고민할 때는 많았는데 무엇을 지울지 고민하게 될 줄은 전혀 몰랐습니다.
❗ 페이블 5 사용법을 쉬운 영어로 정리한 X 게시물 한 편이 150만 회 이상 조회됐다.
❗ 앤트로픽 테스트에서 '실제 도구 실행 결과와 대조하라'는 지시 하나만으로 근거 없는 완료 보고가 거의 사라졌다.
❗ 페이블 5는 6월 9일 공개 후 수출 통제 문제로 단 4일 만에 접근이 중단됐다가 6월 말 다시 해제됐다.

## 📚 핵심 용어
- **다이나믹 워크플로우스:** 한 세션 안에서 수백 개의 서브 에이전트를 병렬로 생성·조율하는 클로드 코드의 작업 분산 방식. / 대형 건설 현장의 현장소장처럼, 혼자 벽돌을 쌓지 않고 철근팀·배관팀·전기팀을 동시에 지휘해 공기를 단축하는 구조다. / 기존 단일 대화는 직원 한 명이 순서대로 처리, 다이나믹 워크플로우스는 팀 전체가 동시에 처리. 차이는 병렬성과 속도.
- **Creator-Verifier 패턴:** 작업을 수행한 에이전트와 별개의 새 에이전트가 결과를 독립적으로 검증하는 이중 확인 구조. / 자기가 쓴 글은 오탈자를 못 찾듯, 결과물을 모르는 제3자에게 교정을 맡기는 것과 같다. / 자기검증은 작성자가 자기 글을 교정하는 것(편향 있음), Creator-Verifier는 외부 교열자를 쓰는 것(편향 없음). 중요한 작업일수록 후자가 정확하다.
- **추론 수준:** 페이블 5가 응답 전 얼마나 깊이 생각할지를 Low·Medium·High·XHigh로 조절하는 설정값. / 편의점에 걸어가는 일엔 택시가 필요 없듯, 작업 난이도에 맞는 '두뇌 출력'을 선택해 비용과 속도를 최적화한다. / 모든 작업에 XHigh를 쓰는 것은 심부름에 관광버스를 대절하는 것. 적합한 수준 선택이 핵심 차이.
- **마이크로매니징 프롬프트:** 버튼 색상·픽셀·순서·허락 요청 등 방법까지 세세하게 지정해 AI의 자율 판단을 막는 과도한 지시 방식. / 유능한 직원에게 키보드 치는 순서까지 알려주는 상사처럼, 지시가 많을수록 상대는 판단을 멈추고 지시만 따른다. / 맥락 중심 프롬프트는 '왜'를 주고 방법을 위임, 마이크로매니징 프롬프트는 '어떻게'까지 규정. 전자가 더 나은 결과를 낸다.
