# 클로드 코드와 코덱스 업데이트 빠르게 살펴보기 | 현업이 알려주는 AI 에이전트

## 🧠 이해 (Understand)
- **Summary:** AI 코딩 에이전트(코덱스, 클로드 코드)가 CLI 터미널에서 출발해 브라우저, 슬랙, 예약 실행까지 작업 표면을 계속 넓혀가고 있다. 직업 대체보다는 '업무 단위별 자동화'가 빠르게 진행 중이며, 논리적으로 설명 가능하고 검증 가능한 업무부터 AI가 먼저 뜯어가고 있다. 개발 업무는 이미 수십 년간 테스트·머지·리뷰 등 검증 프로세스가 코드로 갖춰져 있어 에이전트 진입이 쉬웠다. 이제 코드 생성 자체의 가치는 0에 가깝고, 결과물의 퀄리티를 높이는 '검증 프로세스 설계'가 핵심 역량이 됐다. 도메인별 검증 방식은 다른 도메인에 이식 불가하므로, 범용 하네스가 아닌 도메인 특화 하네스가 필수다.
- **Core Message:** AI가 업무를 단위별로 자동화해 가는 속도는 '검증 가능성'에 달려 있으며, 이제 코드 생성보다 검증 프로세스와 도메인 특화 하네스 설계가 진짜 역량이다.
> 코드 한 줄 더 AI가 만들어 주는 거, 사실 그거의 가치는 이제 거의 0입니다.
> 검증하기 쉬운 일부터 자동화되는 속도가 굉장히 빨라진다.
> 그 업무를 책 이렇게 정리해서 쓰실 수 있고, 그 업무의 최종 꼴을 검증 가능한 형태로 만들 수 있는 거라면 그냥 쉽게 AI가 대체를 해 나가고 있다.
❗ 코덱스의 레코드 앤 리플레이 기능은 발표자가 자료를 준비한 지 4일 만에 실제 출시됐다 — AI 발전 속도가 분석 속도를 앞질렀다.
❗ 개발자 업무는 수십 년 전부터 테스트·머지·리뷰 프로세스가 코드로 갖춰져 있어, AI 에이전트가 다른 직군보다 훨씬 빠르게 침투할 수 있었다.
❗ 연속 작업 성공률이 특별한 조치 없이 34%로 급락하지만, 하네스를 잘 설계하면 70~80% 수준을 유지할 수 있다.

## 📚 핵심 용어
- **하네스(Harness):** AI 에이전트가 특정 업무를 안정적으로 수행하도록 잡아주는 검증·워크플로우 구조. / 공장 컨베이어벨트의 지그(Jig)와 같다. 작업자(AI)가 달라져도 제품이 일정 품질로 나오게 잡아주는 틀. / 모델은 엔진 성능이고, 하네스는 도로·신호·규칙이다. 엔진이 좋아도 도로 없이는 목적지에 못 간다.
- **암묵지(안목지) vs 형식지:** 암묵지는 말로 설명하기 어려운 경험적 노하우, 형식지는 문서나 규칙으로 명시된 지식. / 베테랑 요리사의 '손맛'은 암묵지, 레시피 책은 형식지다. AI는 레시피(형식지)만 따를 수 있다. / 형식지는 자동화 가능, 암묵지는 현재 자동화 불가. 자동화 속도의 병목은 암묵지를 형식지로 바꾸는 작업이다.
- **컴퓨터 유즈(Computer Use):** AI가 화면을 보고 클릭·타이핑 등 실제 컴퓨터 조작을 사람처럼 수행하는 기능. / AI가 마우스와 키보드를 직접 잡는 것. 원격으로 내 PC를 대신 조작해 주는 인턴 직원 같다. / 기존 자동화(RPA)는 정해진 좌표를 클릭하지만, 컴퓨터 유즈는 화면을 '보고' 맥락에 따라 유연하게 조작한다.
- **레코드 앤 리플레이(Record & Replay):** 사용자의 작업 과정을 AI가 녹화했다가 자동 실행 가능한 스킬로 변환하는 기능. / 엑셀 매크로 녹화처럼, 내가 하는 걸 보여주면 AI가 그대로 반복 실행해 주는 것. / 기존 매크로는 정확히 같은 화면 상태에서만 작동하지만, 레코드 앤 리플레이는 AI가 변수에 유연하게 대응한다.

  - 담당: 나 (+ 해당 업무 담당자와 협의)

- [ ] 코덱스 레코드 앤 리플레이 기능 직접 체험 — 반복 수작업 1개를 골라 녹화 후 스킬 생성까지 완료 — ⏰ 이번 주 · ⚡ 1~2시간
  - 담당: 나
  - 이유: 이 기능은 코드 작성 없이 AI가 내 작업을 학습하게 하는 진입 장벽 최저 자동화 경로다. 직접 해봐야 한계와 가능성을 파악할 수 있다.
