# 100만 토큰시대! 앤트로픽이 알려준 클로드코드 컨텍스트 관리법

## 🧠 이해 (Understand)
- **Summary:** 클로드 코드 사용 시 AI가 '멍청해지는' 현상은 컨텍스트 과부하 때문이다. 100만 토큰 창이 생겼어도 30~40만 토큰부터 이미 성능 저하가 시작된다. 해결책은 자동 컴팩션 대신 직접 요약(뭘 남길지 지정), 상태를 JSON으로 저장 후 클리어, 주기적 목표 리마인드, 서브 에이전트 활용, 실수 시 리와인드(ESC 두 번)다. 컨텍스트를 '깨끗한 책상'처럼 유지하는 것이 핵심이다.
- **Core Message:** 클로드가 갑자기 멍청해지는 건 모델 문제가 아니라 컨텍스트 관리를 안 해서 생기는 문제이며, 책상을 주기적으로 정리하듯 컨텍스트를 의도적으로 관리하면 해결된다.
> 얘 왜 이렇게 멍청해졌지? — 이건 모델이 멍청해진 게 아니라 여러분이 잘못 쓰고 있어서 그런 겁니다.
> 절반도 안 썼는데 이미 클로드 머리 흐려지고 있습니다.
> 수정하는 게 아니라 이건 안 한 걸로 하자. 없던 일로 하자가 정답입니다.
❗ 컨텍스트 성능 저하는 100만 토큰 창의 40%도 안 되는 30~40만 토큰부터 이미 시작된다고 Anthropic 개발자들이 직접 밝혔다.
❗ 자동 컴팩션은 AI가 작업 도중 갑자기 요약을 시작하며, 이미 성능이 저하된 상태에서 최근성 편향으로 오래된 정보를 대부분 날려버린다.
❗ 잘못된 AI 응답에 수정 프롬프트를 추가하면 실패작 자체가 컨텍스트에 남아 이후 컴팩션 때 함께 요약되어 오염이 누적된다.

## 📚 핵심 용어
- **컨텍스트 부패(Context Degradation):** 컨텍스트에 정보가 과도하게 쌓여 AI가 무엇에 집중해야 할지 판단하지 못하는 현상 / 책상 위에 서류 천 장을 쌓아두면, 정작 중요한 서류 세 장을 못 찾는 것과 같다. / 컨텍스트 부패는 정보가 많아서 생기는 혼란이고, 컴팩션은 그 혼란을 줄이려는 시도지만 무엇이 빠졌는지 모른다는 점이 다르다.
- **컴팩션(Compaction):** 쌓인 컨텍스트를 AI가 자동 또는 수동으로 요약해 압축하는 기능 / 서류 천 장을 한 장으로 요약하는 것. 편리하지만 무엇이 빠졌는지 아무도 모른다. / 컴팩션은 맥락을 다음 창으로 이어갈 때, 클리어는 완전히 새 작업을 시작할 때 쓴다.
- **서브 에이전트(Sub-agent):** 메인 클로드와 별도의 독립된 컨텍스트 창을 가진 또 다른 클로드 인스턴스 / 심부름꾼에게 도서관 조사를 맡기고, 결과 요약본 한 장만 받는 것. 중간 과정은 심부름꾼 책상에서 끝난다. / 메인 에이전트는 모든 중간 과정이 컨텍스트에 쌓이지만, 서브 에이전트는 결과만 전달하므로 메인 컨텍스트가 오염되지 않는다.
- **리와인드(Rewind):** ESC 두 번으로 잘못된 응답 이전 상태로 되돌려 해당 시도를 컨텍스트에서 완전히 지우는 기능 / 문서 작업 중 실수한 내용을 Ctrl+Z로 없던 일로 되돌리는 것과 같다. / 수정 프롬프트를 추가하면 실패작이 컨텍스트에 남지만, 리와인드는 실패한 시도 자체를 컨텍스트에서 삭제한다.
