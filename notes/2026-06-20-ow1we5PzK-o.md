# The Multi-Agent Architecture That Actually Ships — Luke Alvoeiro, Factory

## 🧠 핵심 요약
- **한 줄 메시지:** AI의 지능이 아닌 인간의 '주의'가 병목인 시대에, 멀티 에이전트 Missions 시스템은 사전 정의된 검증 계약과 구조화된 핸드오프를 통해 수십 일 동안 자율적으로 소프트웨어를 개발할 수 있다.
- **요약:** 소프트웨어 엔지니어링의 병목은 이제 AI의 지능이 아니라 인간의 '주의(attention)'라는 전제에서 출발한다. 발표자 Luke는 Factory에서 개발한 'Missions'라는 멀티 에이전트 시스템을 소개하며, 이 시스템이 수일~수십 일에 걸쳐 자율적으로 코딩 작업을 완수하는 방식을 설명한다. Missions는 오케스트레이터(계획), 워커(구현), 밸리데이터(검증) 세 가지 역할로 구성된 직렬 실행 아키텍처다. 핵심 혁신은 '검증 계약(Validation Contract)'으로, 코딩 시작 전에 완료 조건을 정의해 테스트가 구현에 의해 오염되는 것을 방지한다. 에이전트 간 컨텍스트 손실 문제는 '구조화된 핸드오프(Structured Handoff)'로 해결하며, 각 워커는 작업 완료 시 상세 인수인계 문서를 작성한다. 병렬 실행 대신 직렬 실행을 선택한 이유는 에이전트 간 충돌·중복 작업·아키텍처 불일치로 인한 오류율 급증 때문이다. 각 역할(계획/구현/검증)에 최적화된 서로 다른 LLM 모델을 배치하는 '모델 불가지론적 아키텍처'를 채택해 특정 공급사에 종속되지 않는다. Factory의 가장 긴 Mission은 16일간 실행되었으며, 최종 코드베이스의 50%가 테스트 코드, 90% 커버리지를 달성했다. 이 시스템은 하드코딩된 상태 머신 대신 프롬프트와 스킬로 오케스트레이션 로직을 정의해, 새 모델이 출시될수록 성능이 자동으로 향상되도록 설계됐다.
- **검증 계약 (Validation Contract):** 코딩 시작 전 계획 단계에서 작성하는, 구현과 독립적인 완료 조건 명세서. / 건물 짓기 전에 감리 기준을 먼저 확정하는 것. 시공사가 아닌 제3자가 기준을 정해야 눈속임이 없다.
- **구조화된 핸드오프 (Structured Handoff):** 에이전트가 작업 완료 시 다음 에이전트를 위해 작성하는 표준화된 인수인계 문서. / 병원 교대 근무 시 간호사가 작성하는 인계 차트. 다음 담당자가 처음부터 다시 파악하지 않아도 된다.
- **크리에이터-베리파이어 패턴 (Creator-Verifier):** 구현 에이전트와 검증 에이전트를 분리해 각자 독립적 컨텍스트로 작동하는 설계 패턴. / 글쓴이가 직접 교정하면 오타를 못 보는 것처럼, 만든 사람과 검토하는 사람을 반드시 분리한다.
- **Droid Whispering:** 서로 다른 LLM들이 조합될 때 어떻게 상호작용하고 어디서 실패하는지를 직관적으로 파악하는 역량. / 오케스트라 지휘자가 각 악기의 특성과 약점을 알아야 최적의 편성을 짜듯, 각 모델의 강약점을 알아야 역할 배치를 잘할 수 있다.
