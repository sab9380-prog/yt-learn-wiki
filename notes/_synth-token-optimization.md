# 토큰 최적화 (Token Optimization) 종합

## 핵심 공통 메시지

모든 노트가 동의하는 한 가지: **AI는 매번 처음부터 모든 것을 읽는다 — 그게 낭비의 근원이다.**

토큰 = AI가 정보를 처리하는 단위이자 곧 돈이다. 같은 작업을 해도 어떻게 정보를 준비하느냐에 따라 비용이 84~95%까지 차이난다. [[2026-05-22-AI-토큰-84-절감-LLM-Wiki-패턴-Karpathy가-제안한]] [[2026-05-22-Andrej-Karpathy-덕분에-모두의-Claude-Code가]]

## 해결 전략 3가지 (공통 방향)

### 1. 정보를 미리 압축한다 — LLM 위키
원본 문서 383개(47,000토큰) → 위키 13개(7,700토큰)로 **84% 절감**. 매번 도서관에 가는 대신, 미리 요약 노트를 만들어 두는 방식. [[2026-05-22-AI-토큰-84-절감-LLM-Wiki-패턴-Karpathy가-제안한]] [[2026-05-22-Andrej-Karpathy-덕분에-모두의-Claude-Code가]]

### 2. 구조를 AI 친화적으로 만든다 — 코드베이스·세컨드 브레인
- **코드베이스 카토그래피**: AI가 처음 들어와도 진입점을 1분 안에 찾을 수 있는 지도 제공 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- **Graphify**: 코드베이스를 지식 그래프로 변환 → 전체를 매번 읽지 않고 요약 맵으로 답변 [[2026-06-11-Claude-Code-Graphify-Insane-Agentic-OS]]
- **세컨드 브레인**: 개인·팀의 모든 맥락을 AI가 읽을 수 있는 형태로 축적 → 관련 정보만 골라 읽음 [[2026-05-22-5-Skills-to-Build-an-AI-Operating]]

### 3. 비용을 사전·사후로 통제한다
- **사후**: 토큰 대시보드로 캐시 적중률·고비용 세션 분석 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- **사전**: 코스트 게이트(임계값 초과 시 자동 경고·차단) [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- **위임**: 비싼 모델은 핵심 판단만, 단순 작업은 저렴한 모델에 분산 → 68% 절감 [[2026-05-22-클로드코드채널을-통해-Hermes-Agent를-구독으로만-쓴다고]]
- **예산 한도**: 코덱스 Goal 기능처럼 토큰 예산 내 작업 후 자동 종료 [[2026-05-22-Codex의-이-기능은-반드시-쓰셔야-합니다-goal-마스터코스]]

## 서로 다른 강조점

- **비용 관점**: 토큰을 돈처럼 경영 지표로 관리하라 — 직원 수 대신 토큰 사용량이 실질 생산성을 나타낸다 [[2026-05-22-비교-표시-방식-4-옵션-비교-재열님-결정용]]
- **구조 관점**: 절약 구호는 소용없다. 자동으로 강제하는 훅과 대시보드가 필요하다 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- **복리 관점**: 위키·세컨드 브레인은 사용할수록 맥락이 쌓여 토큰 효율이 복리로 높아진다 [[2026-05-22-5-Skills-to-Build-an-AI-Operating]] [[2026-05-22-Andrej-Karpathy-덕분에-모두의-Claude-Code가]]
