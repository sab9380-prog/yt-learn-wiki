# 토큰 최적화 종합 노트

## 핵심 문제: 왜 최적화가 필요한가?

모든 노트가 공통으로 지적하는 출발점은 **AI가 매번 처음부터 전체를 읽는 비효율**이다.

- 383개 문서를 그냥 넘기면 47,000 토큰 → LLM 위키로 압축하면 7,700 토큰 (84% 절감) [[2026-05-22-AI-토큰-84-절감-LLM-Wiki-패턴-Karpathy가-제안한]]
- AI 레디가 안 된 코드베이스에서 에이전트 토큰의 약 80%가 탐색에만 소모 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- 한국어 프롬프트는 같은 내용을 영어로 쓸 때보다 토큰 1.5~2배 더 소모 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]

## 3가지 접근법: 서로 다른 레이어

노트들은 각기 다른 레이어에서 최적화를 다룬다. 이를 합치면 하나의 완성된 그림이 나온다.

### ① 입력 압축 — "AI에게 넘기는 정보 자체를 줄여라"

| 방법 | 효과 | 출처 |
|---|---|---|
| **LLM 위키** (원본 → 요약본 미리 생성) | 84~95% 절감 | [[2026-05-22-AI-토큰-84-절감-LLM-Wiki-패턴-Karpathy가-제안한]] [[2026-05-22-Andrej-Karpathy-덕분에-모두의-Claude-Code가]] |
| **Graphify** (코드베이스 → 지식 그래프) | 대화당 절감액 달러 단위로 확인 가능 | [[2026-06-11-Claude-Code-Graphify-Insane-Agentic-OS]] |
| **세컨드 브레인** (맥락 사전 구조화) | 관련 정보만 골라 읽어 비용 절약 | [[2026-05-22-5-Skills-to-Build-an-AI-Operating]] |
| **AI 레디 코드베이스** (카토그래피 + 세이니티) | 탐색 비용 80% 원천 차단 | [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]] |

> 공통 비유: 책 전체를 매번 읽는 대신, 미리 만들어둔 목차·요약·지도만 보는 것.

### ② 캐시 활용 — "같은 내용은 1/10 가격에 재사용"

**프롬프트 캐시**가 핵심 레버. 단, 세션 중 claude.md를 수정하거나 모델을 바꾸면 캐시가 전부 무효화되어 누적 비용이 급증한다. [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]

### ③ 사전 통제 — "쓰고 나서 후회 말고, 쓰기 전에 막아라"

- **코스트 게이트**: 세션·PR 단위 토큰 임계값 설정 → 초과 시 경고·강제 압축 [[2026-07-01-Meta에서-배운-실전-테크닉-AI가-길-잃지-않는-코드베이스-토큰]]
- **토큰 예산 관리**: 코덱스 Goal 기능의 실시간 모니터링 → 예산 내 자동 종료 [[2026-05-22-Codex의-이-기능은-반드시-쓰셔야-합니다-goal-마스터코스]]
- **토큰 위임**: 고비용 모델(클로드)이 단순 작업을 저비용 모델(코덱스)에게 분산 → 68% 절감 [[2026-05-22-클로드코드채널을-통해-Hermes-Agent를-구독으로만-쓴다고]]
