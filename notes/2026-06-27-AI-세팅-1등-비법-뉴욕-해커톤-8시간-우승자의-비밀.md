# AI 세팅 1등 비법, 뉴욕 해커톤 8시간 우승자의 비밀

## 🧠 이해 (Understand)
- **Summary:** GitHub 별 17만 개를 받은 'Everything Claude Code(ECC)'는 63개의 특화 AI 에이전트와 249개의 스킬로 소프트웨어 개발 전 과정을 자동화하는 오케스트레이션 시스템이다. 뉴욕 해커톤에서 한 팀이 이 시스템으로 8시간 만에 1등을 차지했고, Y콤비네이터 CEO는 60일간 60만 줄의 코드를 혼자 배포했다. 핵심 강점은 에이전트 역할 분리(기획·개발·테스트·보안)로 AI의 '아첨 현상'을 제거하고, 컨텍스트 자동 압축으로 API 비용을 60% 절감한다는 점이다. 보안 위협(프롬프트 인젝션)과 컨텍스트 붕괴라는 두 가지 치명적 함정이 존재하며, 이를 피하려면 활성 MCP 도구를 10개 미만으로 제한해야 한다. 앞으로의 개발 경쟁력은 코딩 속도가 아닌 AI 워크플로우를 설계하고 통제하는 '오케스트레이터' 역량에 달려 있다.
- **Core Message:** 코딩 실력보다 AI 에이전트들의 워크플로우를 설계·통제하는 오케스트레이터 역량이 앞으로의 개발 경쟁력을 결정한다.
> 현대 개발의 경쟁력은 코딩 실력이 아니라 AI를 통제하는 시스템 구축에 있다.
> 단순한 도구가 아니라 내 프로젝트를 먹고 자라는 하나의 유기체인 셈입니다.
> 앞으로 살아남는 개발자는 코드를 빨리 치는 사람이 아니라 AI들의 워크플로우를 기획하고 통제하는 오케스트레이터가 될 것입니다.
❗ ECC는 GitHub에서 별 17만 개를 받았으며, 63개의 에이전트와 249개의 스킬로 구성되어 있다.
❗ Y콤비네이터 CEO가 ECC 기반 시스템으로 60일간 혼자 60만 줄의 코드를 배포했다.
❗ 컨텍스트 자동 압축 설정 하나만으로 API 비용을 60% 절감할 수 있다.

## 📚 핵심 용어
- **AI 오케스트레이션:** 여러 AI 에이전트에게 역할을 나눠 맡기고 결과를 통합해 하나의 작업을 완성하는 자동화 방식. / 오케스트라 지휘자처럼, 바이올린·타악기·관악기 파트를 따로 지휘해 하나의 곡을 완성하는 것과 같다. / 단일 AI에게 모든 걸 묻는 방식은 1인이 모든 악기를 연주하는 것, 오케스트레이션은 각 파트 전문가를 두는 것—품질과 교차검증이 핵심 차이다.
- **컨텍스트 붕괴:** AI의 기억 용량(컨텍스트 창)이 가득 차 프로젝트 핵심 정보를 잊어버리는 현상. / 메모장이 꽉 차서 앞 내용을 지워야 새 메모를 쓸 수 있는 상황처럼, AI도 대화가 길어지면 초반 지시를 잊는다. / 컨텍스트 붕괴는 AI가 '기억 손실'을 겪는 것, 자동 압축은 '요약 노트'를 만들어 핵심만 유지하는 것—비용과 품질 모두 차이 난다.
- **프롬프트 인젝션:** 외부 파일이나 입력값에 숨겨진 악성 명령이 AI를 오작동시키는 보안 공격. / 투명 잉크로 쓴 '지시문'이 문서에 숨겨져 있어, AI가 읽는 순간 나쁜 명령을 실행하는 것과 같다. / 일반 해킹은 사람의 실수를 노리지만, 프롬프트 인젝션은 AI의 '지시 따르기' 본능을 노린다—AI 권한이 클수록 피해가 커진다.
- **MCP(Model Context Protocol):** AI 에이전트가 사용할 외부 도구·플러그인을 등록·관리하는 설정 파일. / 스마트폰 앱 설치 목록처럼, 어떤 도구를 AI에게 허용할지 목록으로 관리하는 것이다. / MCP에 도구를 등록하는 것과 실제 활성화하는 것은 다르다—등록은 많아도 되지만 동시 활성화는 10개 미만으로 제한해야 컨텍스트 붕괴를 막는다.
