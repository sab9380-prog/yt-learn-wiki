## 1. Claude Code로 별도 자동화 도구 만들기

**🔧 실제로 하는 일**
우리 시스템과는 별개의 새로운 프로그램(예: 상품 태그 추출기)을 Claude Code로 만드는 작업입니다. youtube-learn-auto의 영상 요약·자막 처리·위키 노트 생성 방식에는 손댈 것이 없고, 독립적인 새 도구 개발입니다.

> 영상 원문: Claude Code를 설치하고, 위에서 생성한 시스템 프롬프트를 붙여 넣어 반복 작업 자동화 프로그램(예: 상품 태그 추출기, 자막 생성기) 하나를 실제로 만들어 본다. — ⏰ 2주 내 · ⚡ 2시간

**✅ 이걸 하면 좋아지는 것**
우리 시스템과는 관련이 적습니다.

**⚠️ 걱정되는 점**
우리 시스템과는 관련이 적습니다. 새로운 별도 프로그램 개발이지, youtube-learn-auto 개선이 아닙니다.

**🔎 얼마나 믿을 만한가**
- 바로 코드로 옮길 수 있을 만큼 구체적입니다.
- 여러 영상이 반복해서 다룬 주제라 근거가 두텁습니다.
- 우리 시스템의 분석·자막·위키 모두에 걸칩니다.

**📎 어디서 나왔나**: [[2026-07-08-클로드-페이블5-100-사용-방법]] — 클로드 페이블5 100% 사용 방법 | 딱 1가지만 따라해 보세요
  영상이 이걸 권한 이유: 프롬프트 품질 차이가 결과물 퀄리티에 직접 영향을 미치므로, 최적화된 프롬프트로 Claude Code를 구동하면 완성도 높은 도구를 단번에 얻을 수 있다.

## 2. settings.json에 비용 절감 설정 3가지 적용

**🔧 실제로 하는 일**
youtube-learn-auto의 Claude API 호출 설정을 Sonnet 모델, maxThinkingTokens 10000, subAgentModel Haiku로 변경하여, 영상 분석 비용을 80% 이상 절감합니다.

> 영상 원문: settings.json 파일에서 3가지 비용 절감 설정 적용 (model: Sonnet, maxThinkingTokens: 10000, subAgentModel: Haiku)

**✅ 이걸 하면 좋아지는 것**
매일 2~5개 영상을 분석하는 현재 사용량에서 다음 달 Claude 비용을 대폭 줄일 수 있으며 즉시 적용 가능합니다.

**⚠️ 걱정되는 점**
Sonnet과 Haiku 모델 전환이 영상 요약·분석 품질에 미치는 영향을 실제로 테스트해야 합니다. 비용 절감이 분석 정확도 저하를 초래할 수 있습니다.

**🔎 얼마나 믿을 만한가**
- 바로 코드로 옮길 수 있을 만큼 구체적입니다.
- 여러 영상이 반복해서 다룬 주제라 근거가 두텁습니다.
- 우리 시스템의 한 부분에 닿습니다.

## 3. 옵시디언 자동 저장 크론잡 연결

**🔧 실제로 하는 일**
youtube-learn-auto가 Claude로 분석한 결과를 옵시디언에 저장할 때, 3시간 간격 자동 저장 크론잡(또는 Make·n8n)을 추가하여 수동 저장에만 의존하지 않도록 합니다.

> 영상 원문: Claude나 Codex 등 사용 중인 에이전트에 '옵시디언 참조 호출' 규칙을 설정하고, 3시간 간격 자동 저장 크론잡 또는 유사 자동화(Make·n8n 등)를 연결해 테스트 루프 1회 실행

**✅ 이걸 하면 좋아지는 것**

**⚠️ 걱정되는 점**
크론잡 실행 빈도와 Railway 무료 시간 제한 사이의 충돌 가능성이 있으며, 중복 저장이나 데이터 손실 방지 로직이 필요합니다.

**🔎 얼마나 믿을 만한가**

- 여러 영상이 반복해서 다룬 주제라 근거가 두텁습니다.

## 4. AI 분석 정확도 베이스라인 측정

**🔧 실제로 하는 일**

> 영상 원문: 정답을 아는 테스트 질문 20~30개 만들어 AI 정확도 베이스라인 측정 — ⏰ 2주 내 · ⚡ 1~2시간

**✅ 이걸 하면 좋아지는 것**
지시문 개선이나 자막 처리 방식 변경 후 실제 효과를 수치로 확인할 수 있으므로, 향후 시스템 개선을 검증하는 근거가 생깁니다.

**⚠️ 걱정되는 점**
테스트 셋 구성이 영상 주제나 장르의 편향을 반영할 수 있으며, 정확도 측정 기준 자체를 정의하기가 모호할 수 있습니다.
