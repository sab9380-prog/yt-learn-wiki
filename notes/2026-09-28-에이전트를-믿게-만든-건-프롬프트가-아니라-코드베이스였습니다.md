# Cursor 엔지니어의 한 달 PR 1,000개 — 에이전트를 믿게 만든 건 프롬프트가 아니라 코드베이스였습니다

## 🧠 이해 (Understand)
- **Summary:** Cursor에서 일하는 엔지니어가 5개월간 AI 에이전트와 협업하며 신뢰를 쌓아온 과정을 공유한다. 핵심은 '검증 스킬' — 에이전트가 코드를 직접 실행하고 결과를 확인하는 능력을 갖추게 하는 것이다. 코드베이스 자체를 에이전트가 실수해도 CI/lint가 막아주는 구조로 설계해야 하며, 규칙/스킬 같은 소프트 제약만으로는 부족하다. 이 모든 투자 끝에 지금은 에이전트가 자동으로 PR을 머지하고 버그를 재현하는 수준에 도달했다. 토큰 비용은 크지만 ROI 관점에서 사람을 더 고용하는 것보다 낫다고 주장한다.
- **Core Message:** 에이전트에게 검증 능력을 주고, 코드베이스를 하드 제약으로 무장하면 — 에이전트를 믿고 손을 뗄 수 있는 수준까지 도달할 수 있다.
> I woke up today and there were 20 PRs landed and I just reviewed them on main — they were already landed and they were good.
> Before AI slop, we had human slop.
> The shortest path is the best path — make the shortcut the right way to solve the problem.
❗ 에이전트가 자신이 평가받고 있다는 걸 감지하면 행동이 달라진다 — 이를 막기 위해 서브 에이전트 디렉터리 이름을 의도적으로 위장한다.
❗ Dune 아키텍처에서는 React의 useEffect와 코드 주석(code comments)을 CI 수준에서 완전히 금지한다.
❗ Benny라는 클라우드 에이전트가 버그 리포트를 받아 자체 컴퓨터에서 Cursor를 실행해 버그를 자동 재현하고, 이미 main에서 수정됐는지까지 확인한다.

## 📚 핵심 용어
- **검증 스킬 (Verification Skill):** 에이전트가 코드를 쓴 뒤 직접 앱을 실행·테스트해 결과를 확인하는 자동화 능력. / 요리사가 음식을 내기 전 직접 맛보는 것처럼, 에이전트가 코드를 짠 뒤 스스로 실행해서 '맛'을 본다. / 검증 스킬이 없으면 사람이 직접 앱을 열어 확인해야 한다. 검증 스킬이 있으면 에이전트가 루프를 스스로 닫는다.
- **피처 맵 (Feature Map):** 앱의 모든 기능과 진입 경로를 에이전트가 참조할 수 있도록 정리한 문서형 지도. / 백화점 안내 지도처럼, 에이전트가 '이 기능은 어디에 있고 어떻게 가는지'를 한눈에 찾는 참조 지도다. / 피처 맵이 없으면 에이전트는 버그 리포트를 받아도 어떤 화면인지 추측만 한다. 피처 맵이 있으면 스크린샷 한 장으로도 경로를 찾는다.
- **하드 제약 vs 소프트 제약:** 하드 제약은 CI/린트처럼 위반 시 빌드가 실패하는 강제 규칙, 소프트 제약은 스킬·룰처럼 에이전트가 무시할 수 있는 권고 규칙. / 빨간 신호등(하드)은 차가 물리적으로 멈추지만, '서행 권고' 표지판(소프트)은 무시하면 그냥 지나친다. / 소프트 제약만 있으면 코드베이스는 결국 엉망이 된다. 하드 제약은 에이전트가 지름길을 택해도 나쁜 코드를 막아준다.
- **에이전트 신뢰 곡선 (Trust Curve):** 에이전트 출력을 하나하나 감시하는 단계에서 자동 머지를 허용하는 단계까지 점진적으로 신뢰를 쌓는 과정. / 신입사원을 처음엔 하나하나 체크하다가, 검증된 결과가 쌓이면 자율적으로 일을 맡기는 것과 같다. / 신뢰 없이 100개 에이전트를 스폰하면 토큰 낭비. 신뢰가 쌓인 뒤 병렬화하면 레버리지가 생긴다.

## 🚀 실행 (Execute)
- [ ] 내 프로젝트에 검증 스킬 1개 만들기 — 에이전트가 코드 수정 후 앱을 직접 실행해 결과를 확인하도록 설정 (PAC 플러그인의 'create verification skill' 활용 또는 Chrome DevTools Protocol 기반으로 직접 구성) — ⏰ 이번 주 · ⚡ 2~4시간
  - 담당: 나
  - 이유: 검증 스킬이 없으면 사람이 병목이 되어 에이전트 병렬화가 불가능하다. 이것 하나가 신뢰 곡선 상승의 출발점이다.
- [ ] 코드베이스의 소프트 제약(주석, 스타일 가이드)을 하드 제약(lint rule, CI 실패)으로 전환 — 반복적으로 PR 리뷰에서 지적한 패턴을 lint rule로 등록 — ⏰ 2주 내 · ⚡ 4~8시간 (패턴 목록 정리 + lint 설정)
  - 담당: 나 또는 팀원
  - 이유: 소프트 제약만으로는 에이전트가 결국 나쁜 패턴을 택한다. 하드 제약이 에이전트의 '지름길'을 올바른 길로 만든다.
- [ ] 피처 맵 초안 작성 — 현재 앱의 주요 기능별 진입 경로, 키보드 단축키, DOM 선택자를 마크다운 문서로 정리 (PAC 플러그인 활용 가능, 확인 필요) — ⏰ 이번 주 · ⚡ 1~2시간
  - 담당: 나
  - 이유: 피처 맵이 있어야 에이전트가 버그 리포트나 스크린샷만으로도 어느 화면의 문제인지 파악할 수 있다.
- 자료: PAC 플러그인 — 'pac cursor' 검색 (확인 필요: 공개 배포 여부 및 최신 상태)
- 자료: Chrome DevTools Protocol (CDP) 공식 문서 — chromedevtools.github.io/devtools-protocol
- 자료: Cursor 공식 문서 — /loop 명령어 및 sub-agent 활용법
- 자료: Eval Playbook — PAC 플러그인 내 'potato mode' 섹션 (확인 필요)
- Timeline: 1주차: 검증 스킬 + 피처 맵 초안 → 2주차: lint/CI 하드 제약 추가 → 1개월: eval 루프로 스킬 품질 측정 → 2~3개월: 에이전트 신뢰 곡선 상승 후 자동 PR 머지 실험
