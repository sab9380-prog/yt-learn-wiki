# 바이브 코딩 (Vibe Coding) 종합

## 핵심 정의 — 노트들이 공통으로 말하는 것

**코딩 지식 없이 자연어(말)로 AI에게 제품을 만들게 하는 개발 방식.** 의도와 목적만 전달하면 AI가 코드를 생성한다. [[2026-07-04-클로드-코드-해커톤2위를-수상한-AI-스타트업의-생존기-이제는-이거]] [[2026-06-24-왕초보도-당장-따라할-수-있는-클로드-디자인-15분-속성-마스터-클래스]] [[2026-05-22-나의-AI-에이전트-전환기-w-클로드-코드-오픈클로]]

비개발자가 3시간 해커톤에서 MVP를 완성하고 [[2026-07-04-클로드-코드-해커톤2위를-수상한-AI-스타트업의-생존기-이제는-이거]], 랜딩 페이지를 1~2시간 내 만들 수 있을 정도로 속도는 검증됐다. [[2026-06-24-왕초보도-당장-따라할-수-있는-클로드-디자인-15분-속성-마스터-클래스]]

---

## 서로 다른 관점·강조점

### ① "만드는 것보다 그 다음이 문제다"
데모는 4일이면 나오지만, **돈 받는 제품**까지 가는 데 두 달이 걸린다. 결제 시스템 심사·멱등성·웹훅 예외처리는 AI가 자동으로 챙기지 않는다. [[2026-07-12-4일-만에-만들었는데-결제-붙이는-데-2달-걸렸습니다]]

### ② "디자인 품질이 평범해지는 함정"
코드를 바로 생성하면 'AI 슬롭' 수준의 결과물이 나온다. 이미지 시안을 먼저 생성 → 에셋 분리 → 코드 구현 순서로 가면 완성도가 올라간다. [[2026-07-01-youtube-com-watch-v-Xe6uonOPX4A]]
design.md에 금지 항목 10줄만 써도 제품 일관성이 크게 개선된다. [[2026-07-12-4일-만에-만들었는데-결제-붙이는-데-2달-걸렸습니다]]

### ③ "진짜 실력은 뭘 물어야 하는지 아는 것"
바이브 코딩의 경쟁력은 코드가 아니라 **올바른 질문과 컨텍스트 설계**에 있다. Anthropic 공식 프롬프트 가이드를 Claude 자신에게 읽혀 최적 프롬프트를 만들게 하는 것이 대표 사례다. [[2026-07-08-클로드-페이블5-100-사용-방법]] [[2026-07-04-클로드-코드-해커톤2위를-수상한-AI-스타트업의-생존기-이제는-이거]]

### ④ "AI 에이전트 시스템으로 확장"
단순 코드 생성을 넘어, AI 에이전트가 효율적으로 일하는 **환경 설계**가 핵심 역량이 됐다. 하네스 엔지니어링으로 업무 80%를 자동화하거나 [[2026-05-22-나의-AI-에이전트-전환기-w-클로드-코드-오픈클로]], LLM 위키 기반 시스템으로 AI의 작업 효율을 높이는 방향이다. [[2026-06-05-UX-UI-디자이너에게-옵시디언이-필수가-되고-있는-이유]]

## ⚠️ 상충·주의점

**가장 큰 함정: "AI 완료 ≠ 내 완료"**

- AI는 기능이 작동하면 완료로 본다. 보안(RLS, Rate Limit, API 키 노출)은 별도로 체크해야 한다. [[2026-05-22-바이브코딩-보안-실수-3가지]]
- AI로 만든 앱 중 상당수가 데이터베이스 비밀번호를 프론트엔드에 노출하거나 접근 제어가 없는 상태로 배포된다. [[2026-05-22-바이브코딩-보안-실수-3가지]]
- "코딩은 전체의 10%, 설정이 나머지 90%"라는 경고처럼, **만드는 것은 제일 쉬운 부분**이다. [[2026-07-12-4일-만에-만들었는데-결제-붙이는-데-2달-걸렸습니다]] [[2026-05-22-바이브코딩-보안-실수-3가지]]

## 한 줄 정의
> **바이브 코딩이란, 코딩 없이 말로 제품을 만드는 방식인데 — "만드는 것"은 이미 해결됐고, 진짜 승부는 디자인 일관성·결제 구조·보안·알리는 시스템을 갖추는 데 있다.**
